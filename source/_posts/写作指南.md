这篇是给自己的备忘，也是模板。新建文章后照着改，不需要时整篇删掉。

## 新建一篇文章

```bash
cd /e/Blogs/hexo-blog
npx hexo new post "文章标题"
```

会在 `source/_posts/` 生成 `文章标题.md`，同时生成一个**同名文件夹**，专门放这篇文章的图片。

打开 md，开头那段 `---` 包起来的是 front-matter，控制文章的元信息：

```yaml
---
title: 文章标题
date: 2026-11-01 10:00:00
tags:
  - 标签A
  - 标签B
categories:
  - 分类名
cover: /img/covers/cover-1.svg
---
```

## 封面

`cover` 一行就是文章卡片和文章页顶部的背景图。三种写法：

**1. 用现成的**（`source/img/covers/` 下有四张，风格统一）

```yaml
cover: /img/covers/cover-1.svg   # 紫夜月牙
cover: /img/covers/cover-2.svg   # 冰蓝波纹
cover: /img/covers/cover-3.svg   # 粉紫光斑
cover: /img/covers/cover-4.svg   # 墨绿星座
```

**2. 用自己的图**：图片放 `source/img/` 下，然后写路径

```yaml
cover: /img/我的封面.jpg
```

**3. 不写**：自动用 `_config.butterfly.yml` 里 `default_cover` 配的那张。

想给不同文章配不同图，就把图丢进 `source/img/covers/`，然后 `cover: /img/covers/xxx.jpg`。

## 分类和标签

两者都在 front-matter 里写，**不用提前创建目录，写了就自动生成**。

- `categories` 是**层级**的，一篇文章一般只归一个。想分层就写成缩进列表：
  ```yaml
  categories:
    - 技术
    - 前端
  ```
  会变成「技术 / 前端」两级。
- `tags` 是**平铺**的，一篇可以有多个，随便加。

写完后，顶部导航的「分类」「标签」页面会自动汇总。

## 放图片

图片丢进文章的同名文件夹，正文直接写文件名：

```markdown
![图片说明](cover.png)
```

不用写路径。多篇文章共用的图（比如 logo）放 `source/img/`，正文写 `/img/xxx.png`。

## 发布上线

```bash
git add -A
git commit -m "post: 文章标题"
git push
```

推完等一两分钟，GitHub Actions 自动构建发布，刷新网站就能看到。

想先在本地看效果：

```bash
npx hexo server
```

浏览器开 `http://localhost:4000`，改 Markdown 会自动刷新。改主题配置（`_config.butterfly.yml`）需要重启才生效。

## 其它常用命令

| 命令 | 作用 |
| --- | --- |
| `npx hexo new post "标题"` | 新建文章 |
| `npx hexo new page "about"` | 新建独立页面 |
| `npx hexo clean` | 清缓存，样式不生效时先跑这个 |
| `npx hexo generate` | 生成静态文件到 `public/` |

## 几个小提醒

- 文件名建议用英文，中文文件名会让文章链接变成一长串编码。标题写中文就行。
- 想置顶某篇，front-matter 里加 `top: true`。
- 摘要用 `<!-- more -->` 手动切，不写就自动截前 500 字。
